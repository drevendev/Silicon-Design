# Roadmap

## Initial foundation

The first version contains principles, typography/color/layout/interaction/accessibility foundations, separate website/app/game guidance, five portable skills, project/review templates, a source register and three fictional visual specimens. Static checks cover the declared repository contracts; the verification note records the narrower rendered checks.

## 2026.11.15.1: working teaching cases and explicit evaluation units

The [release record](research/release-2026-11-15.md) distinguishes already-merged guidance from working corrections and acceptance still unverified. [Fictional before/after cases](examples/craft/README.md) now exercise composition, actual controls, exact totals, glyphs, charts and contextual link preferences. The [synthetic runner](examples/blind-test-demo/README.md) supports whole websites without route ballots, selected pairs and early stopping. PR #4’s missing contracts and PR #24’s attributed fixtures were incorporated through PR #50; the [reconciliation audit](research/pr4-pr24-reconciliation-2026-11-15.md) checks the remaining differences. Better future generations, cost, learning and real-product/owner acceptance remain open; no new model or human study was launched.

## Next: apply it to a real product

Release [2026.11.17.1](research/release-2026-11-17.md) adds original transaction, material, asynchronous-work and offline-control teaching cases. It incorporates later BJH/IdleShop text evidence without revising their results. The open-issue matrix distinguishes completed specimen/guidance work from actual product, zoom, activation and held comparison acceptance. These examples do not complete the real-product trial below.

The [14 November feedback revision](research/feedback-revision-2026-11-14.md) consolidates the existing trials and both v6 owner reports. It implements instruction changes while keeping product adoption, fresh matched evaluation and teaching-specimen work separate. Use its complete feedback map for current implementation ownership; the original outcome criteria remain with their issues.

The [specimen critique](research/specimen-critique.md) has now informed a [working redesign](examples/README.md): an observation journal, a repair desk and a lanternmaker's scene. Their [review](examples/REVIEW.md) distinguishes implemented changes from hypotheses about character. Applying the handbook to an existing real product remains the next validation.

1. Choose one representative flow from an existing product and capture its actual current implementation.
2. Record a project-specific DESIGN.md and compare meaningful directions if identity is changing.
3. Implement one selected direction without changing unrelated behavior.
4. Compare the same content, states and environments before and after; record keyboard, scaling, accessibility and task observations separately.
5. Keep the useful decisions and revise guidance only where evidence supports a broader lesson.

This application is future work. The fictional specimens are not its before/after evidence.

## Expand when usage justifies it

- Repeat the [first matched agent trial](benchmarks/2026-11-03/RESULTS.md) with revised skills, multiple samples and independent human assessment. The first six runs are complete; a comparative win is unproven.
- More theme and localization specimens, including long Cyrillic content.
- Native app and controller-runtime examples with actual device checks.
- A token interchange/export layer if multiple products need it.
- A plugin or installer if maintaining copied skill folders becomes a demonstrated problem.

No automatic redesigns, scheduled work, tool installation or cross-product migration is enabled by this repository.
