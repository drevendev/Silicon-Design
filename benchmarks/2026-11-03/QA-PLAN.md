# Checks fixed before browser review

Source-level self-check counts are not comparable quality scores. The operator checks the same user-facing contract for each member of a pair. Missing adapter IDs are recorded separately from actual task failures.

## All candidates

1. Open each of directions a/b/c fresh at 1280×900; record actual viewport and screenshots. Confirm required material loads, labels/content are present and primary task is discoverable.
2. Inspect each direction at 390×844. Check page-wide overflow, necessary text and access to actions; inspect lower content as needed.
3. Execute the representative flow below in direction a. Switch directions while mid-task; confirm state/context. Inspect secondary/error/completed fixtures as labelled states, separately from executed actions.
4. Inspect default/recovery focus with a limited keyboard pass; leave untested browser zoom, AT and physical-device checks explicit.
5. Parse generated JS; inspect local asset/script/style paths and source for prohibited dependencies/persistence. Run meaningful supplied checks if available, but do not infer browser success from them.

## Judgment and corrections

For each pair record specific losses/ties/strengths in operation and character separately. Locate a finding by selector/state/viewport and consequence; label measured/reproduced versus aesthetic judgment. Describe within-brief variation using dominant object, hierarchy, density, imagery and response to action. Do not invent audience preferences or a universal winning score.

Keep originals frozen. Any extra-feedback revision receives a separate path, effort note and affected recheck; it cannot replace the original comparison.
