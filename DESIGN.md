# The Silicon Design handbook

## Purpose and audience

Help our developers and coding agents make specific, reviewable design decisions for websites, apps and games. The first useful action is adopting one project brief and one representative flow.

## Repository experience

The README explains the outcome, gives a short adoption path, routes to five skills and links visible teaching examples. Detailed foundations and research stay behind explicit links. English is the maintained handbook language; README.ru.md is a concise Russian entry point.

Avoid invented maturity badges, ratings and efficacy claims. Source ideas need boundaries and revisions. Fictional examples remain clearly labelled.

## Visual specimens

The specimen wrapper is a quiet index: system sans, dark ink, visible links, broad outer spacing and numbered sections. It leaves room for three deliberately different inner product directions. Each has a separate filled brief and semantic palette. This wrapper is not the visual identity to impose on consuming projects.

Wide views juxtapose title and introduction. Narrow views stack content in reading order. Local links and native disclosures make the examples inspectable. One simple crafting interaction demonstrates truthful resource feedback; no backend or real game is implied.

## Evidence and limits

Static checks cover the local contracts described in CONTRIBUTING.md. Browser inspection and its limits are recorded in [examples/VERIFICATION.md](examples/VERIFICATION.md). The next meaningful validation is a real product application in the roadmap.
