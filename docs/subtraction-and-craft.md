# Subtraction and the final craft pass

Use for a substantive composition or its review; a small fix needs only its affected region. Standalone skills contain the essential decisions. These are contextual Silicon Design conventions, not accessibility standards or a compulsory style.

## Make the object own attention

Name the object or decision: goods on a shelf, a worker, a document or a purchase. At use size it should lead its labels, frames and explanations.

Start with one enclosing boundary per object. Extra framing needs a functional reason, such as an independent preview or selectable subgroup. Keep useful focus, selection, input and safety boundaries. For uniform records, try one list with dividers before individual cards with repeated padding, badges and accent rails. Cards remain useful for independent objects; lists and centring are not universal requirements.

Choose centring or a comparison edge deliberately. Align corner actions with their header; unrelated badges should not displace them. Inspect both visible glyph and operable target: an invisible hit area does not make a tiny Remove mark recognizable. Preserve useful backgrounds, material and alignment.

## Subtract without losing meaning

For each visible caption, badge, title or repeated sentence, ask what is lost if it disappears. Check relevant states and inputs, not just a populated screenshot.

| Authored example | Bounded correction | Meaning to retain |
| --- | --- | --- |
| “Selling”, “Stock” and `10/50` beside a recognizable meter | Remove duplicate words when count/meter explains the state | Accessible item/stock association; empty, unavailable and unknown distinctions |
| Selected price button followed by the same mode name | Let the named selected control carry the mode | Selection beyond colour, accessible state and signed effects |
| Six worker rows repeat captions and a global explanation | Try shared alignment/dividers and section Help | Identity, assignment, payable wage, blocked reason, safe Pause/Cancel |
| “Shelf is full” repeats a full meter | Omit reassurance when no decision is lost | An understandable reason if the meter cannot explain an unavailable action |

Accessible names cannot replace visible instructions sighted users need. Keep legends, field labels, deficits, lock conditions, recovery and meaningful empty states. Secondary help needs keyboard/touch access and useful focus return; a disabled control cannot be its only entry. Respect fixed-copy/DOM limits.

Place modifiers beside what they change: a price bonus beside price, not stock. Distinguish quote, unit price, quantity and total. The exact total must be visible at commitment: `12,480` cannot become only `12.5K` with precision solely in an accessible name. Secondary history may use reachable detail. Check long names and large/live values at minimum width; reflow without accidental page-wide overflow. Reserve geometry where live values should not move adjacent controls.

## Finish the visual work

Compare original/result at the same content, state, viewport, language and scale before delivery. State when the original is unavailable. Inspect first attention, duplicate words/frames and action clarity. Make a critical correction within budget; record removals or justified retentions. There is no removal quota, extra generation or duty to consume every remaining minute.

Report operation/access, unresolved craft judgment, relative preference and explicit owner acceptance separately. Technical passes establish their tested properties; a winning screen with criticism still needs refinement. A prototype is not automatically adopted.

Inspect task-relevant shared elements along the path. Fix a clipped event chip or clashing icon when authorized; otherwise locate it as an unresolved limitation. Do not silently expand scope or claim a clean result because a defect lives in another component.

For a worked correction see [the fictional workshop](../examples/craft/README.md). It shows the same data and capabilities with edited hierarchy, exact totals and recovery. Its intentionally defective teaching baseline is not a historical generation. Scriptorium’s owner rejected decorative diagonal link arrows: carry that product preference through linked branding, navigation, content and pseudo-elements. Preserve meaningful chart/sort/direction arrows and truthful destination/download/disclosure cues in their own contexts.
