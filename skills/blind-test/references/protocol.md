# Conduct and data contract

## Before dispatch

Record source/package commit IDs; snapshot relevant issues/comments at a stated cutoff; precedence is the current owner brief. Preserve the verbatim common brief and identical short instruction. Keep package-specific workflows out of shared context. Copy complete assigned skill folders and their actual reference closure at the pinned revision; exclude unrelated prior benchmark/evaluation material or prohibit its reading and disclose the access limit. Existing product rules remain, optional environment design skills do not.

Record actual host/model/effort, available shell/browser/build/inspect/network capabilities, concurrency, start/end observations and budget scope. Equal limits are not equal spend. Do neutral source/data/adapter preparation before generation. A necessary later technical amendment must be applied equally, recorded with old/new hashes and announced to every designer; do not call that perfect pre-dispatch preparation. Product merge/publication/issue closure are separate authorities.

For synthetic data, record provenance, save-byte and canonical sorted-GameState SHA-256, seeded identities/RNG and every nondeterminism fix. Use the same main save for every screen/condition; adverse fixtures supplement it. Native validation must pass. Clearly distinguish prepared progress from earned progress. Test fixed-time boot without real-time catch-up and real-engine controlled ticking/actions/reset. Do not replace game/domain code with a static imitation. Keep domain/content/application/persistence values unchanged when the study permits UI only.

Capture every condition uniformly: engine/version, CSS viewport, DPR, browser zoom, locale, fonts, clock, animation policy and full-area rule. Never beautify one condition with different crop, scale, offers, pagination or data. Keep the real shared shell in the main frame. Provide native zoom/scroll and supplementary locale/mobile/full-area views; they do not create extra votes. Restricted artwork may need separate owner-only previews and masked model checks; metadata/load checks do not prove visual acceptance. Preserve licences and reusable-source redistribution restrictions.

## Viewer and corpus

Use neutral artifact IDs and a private map outside voter HTML and filenames. Explain recognition/file-inspection limits. Freeze the evaluation unit and selected comparison format before starting; a whole-site request does not authorize per-route ballots or complete round robin. Display actual voting workload before Start. Skips are missing answers; early stopping is always available.

### New contract: schema 2 / protocol 3

Schema 2 requires explicit surfaces/routes, locale and view lists; legacy product defaults apply only to schema 1. The builder rejects malformed capture records and locale-entry maps before writing output.

Required configuration: `schema_version:2`, `protocol_version:3`, a new `study_id`, integer `seed`, unique `screens` (surface IDs or route orientation labels, excluding `set` and `whole_site`), `supported_locales` (ru/en subset), `supported_views` (desktop/mobile/full subset), neutral `artifacts`, and:

- `evaluation_unit: "whole_site"`: one ballot per selected pair of complete working sites. No route or set ballots. Each artifact supplies `site_dir` (trusted static build directory, relative to the input JSON) and optional `site_entry` (default `index.html`) for a single declared locale. A multilingual site must provide `site_entries`, mapping every declared locale to its actual HTML entry page; the parent language selector loads those pages on both sides. Emitted `site.entries` contains packaged paths, and `site.entry` is the first declared locale’s entry. Single-locale older packages without this optional map remain readable; unsupported multilingual packages are rejected explicitly. The builder copies every file to `sites/<id>/`, removes source paths from the public corpus and records SHA-256 file manifests plus `runtime_package_id`. Relative navigation, styles, images, JSON and scripts run as actual files. Optional `captures` are supplementary PNG data URLs, never extra ballots. Each side owns an independent iframe; navigation does not reset its opponent, pair or draft. The pane shows actual inner width/height in CSS pixels and the HTML document’s declared language; schema-2 whole-site answers optionally retain these as `runtime_display` per side (route, width, height, document_lang). The parent `locale` is the requested condition; the document language is recorded evidence, not proof of translation quality. “Fit” uses the available pane width, so a 1440 px outer window does not mean each website has a 1440 or 1280 px viewport. Width controls resize the actual frame (desktop 1280 / mobile 390 at 100, twice those widths at 200); they do not apply native browser zoom. Reload resumes answers/drafts; it may return site navigation to its entry page.
- `evaluation_unit: "surface"`: exactly one declared surface; captures required for each declared locale/view. Optional self-contained `runtime_b64` opens the prepared runtime.
- `evaluation_unit: "multi_surface"`: captures for the declared surfaces, with explicit `coherence:true` or `false`. Only true adds a separate `set` ballot; confirmation then requires displayed captures for every member surface on both sides. Display history establishes display, never human attention.
- `comparison:{"format":"round_robin","side_control":"seeded"}` selects all unordered pairs with seeded balanced orientation. Or select `{"format":"selected_pairs","side_control":"as_listed","pairs":[{"left":"a","right":"b"}]}` for a smaller defined set. `side_control:"seeded"` also works for selected pairs; orientation is seeded rather than guaranteed balanced for arbitrary small graphs. Duplicate/reversed duplicate and unknown/self pairs are rejected. Screen blocks alternate sides unless as_listed is chosen.

Seven whole-site candidates with round robin produce **21** unique ballots, regardless of route count. Seven candidates with explicitly selected five surfaces and `coherence:true` produce **126** (105 surface + 21 set). Neither 21 tasks nor “7 votes” follows merely from requesting seven websites. Two listed pairs produce two whole-site ballots. No adaptive elimination or score inference is implied by stopping early.

`screen_labels`, `capture_contract`, `runtime_contract`, and `qa_fixture:true` retain their meanings. Captures use `screen/locale/view` keys and PNG data URLs. `runtime_protocol:"idle-review"` enables the legacy prepared clock adapter; absent that contract, controls do not invent interaction semantics.

Multi-file output is a portable **folder**, served locally: run `python -m http.server --bind 127.0.0.1` inside it, then open `http://127.0.0.1:8000/Blind-Test.html`. It publishes nothing externally. The viewer verifies every packaged runtime file before enabling Start. Trusted static output only: iframe sandboxing allows scripts/same-origin/forms/downloads for real navigation and JSON, and is not a security boundary against hostile same-origin code. No hidden source/dependency directories or symlinks are packaged. Supply static output with relative links; backend/server-rendered routes, absolute-root deployment paths and shared-origin storage need an explicit equal adapter/isolation contract. Do not claim unsupported backends work. Distinct static file paths do not isolate shared-origin localStorage; candidate runtimes requiring saved state must be namespaced or served at separate origins before study use.

The included demonstration is synthetic, resets runtime state and forces `qa:true`; it is not a Scriptorium study. Screenshot-only legacy output continues to open offline without a server. Actual runtime and screenshots are labeled separately.

### Historical compatibility

Schema 1 / protocol 1–2 corpora retain the exact old scheduler (per-screen round robin plus set) and session format. Protocol 1 set answers without exposure remain analysable as unverified coherence; protocol 2 requires exposure. Schema 1 with new evaluation fields or protocol 3 is rejected. New-unit sessions use schema 2 and record `evaluation_unit`; older valid single-locale schema-2 sessions without `runtime_display` remain readable with their viewport evidence absent. Strict study/protocol/corpus matching prevents moving old answers onto the new schedule. Do not rewrite completed historical exports or reuse their identity.

New builds declare `corpus_hash_format: typed-ieee754-v1`. Their canonical hash input tags each JSON value by type, represents finite numbers as big-endian IEEE754 binary64 hex, and sorts object keys by UTF-16 code units. This preserves numeric metadata such as DPR1.0,1.25 and scientific notation across Python/JavaScript and avoids numeric-key ordering drift. Integers beyond JavaScript's exact safe range must be strings. Earlier untagged corpora retain their legacy verification path. The runner source hash is part of new corpus identity. Do not repair a mismatched old ID by replacing it manually.

The viewer rejects switching to a corpus built for another runner hash or runtime package. Rebuild under an explicitly agreed protocol instead of silently applying different conduct to old answers. Legacy protocol1 exports lacking exposure remain analysable with that limitation; protocol2 submitted set answers require coverage on both sides. Invalid cursor/preferences/draft structures are rejected before changing progress. Current screenshots must load successfully before confirmation, including a previously reviewed set.

Buttons must be Left / Tie / Right. Selection saves a pending draft without navigating. Next submits the selected preference and current comment, then advances; no chosen option means no submitted answer. Back, reload and export preserve unfinished drafts. Record actual display exposure for each screen on each side in set tasks and block final confirmation until all are displayed. Do not equate exposure with comprehension. Keep defects in their own records, not as extra preference answers. Skip/early-stop leave gaps. Never silently turn omitted or invalid answers into ties.

Exports include schema_version, evaluation_unit for schema 2, study_id, protocol_version, corpus_id, session_id, qa, completion, answers and defects. An answer includes block/screen, pair ID, left/right artifact IDs, winner left/right/tie, comment, timestamp and selected locale/view/zoom; retain side screen selection and exposure history. Validate IDs, sides, duplicate pairs and completion. Reject answers for another corpus/protocol; imports must not replace valid progress on failure. Verify corpus integrity, not its name alone. Keep downloaded JSON as fallback if storage is denied. No method descriptions, designer rationales or results before completion/explicit disclosure.

## QA and analysis

Check real Buy/quantity/refusal/stock/timers, hire/assign/pause/cancel/paid cycles, shelf assign/restock/remove/modes/knowledge gates as applicable. Exercise EN/RU, long labels, large numbers, keyboard/touch/focus and reduced motion. Measure actual text/SVG foreground/background pairs and permitted-asset crops. Viewport reflow/CSS scaling is not native tab zoom. Report PASS/FAIL/UNTESTED/ENVIRONMENT_UNAVAILABLE and distinguish stale selectors/harness faults from product regressions. No screenshot or static contrast calculation proves full accessibility. Bad aesthetics is not a technical reason to drop a participant. Do not run excluded release qualification/heavy simulations.

Use human `qa:false` answers only (`StudyCore.humanSessions` validates and excludes QA sessions). Analyze whole-site, individual-surface and explicit coherence units separately. Keep screen outcomes and set outcomes separate; do not pool percentages from independent provider corpora. If prose conflicts with the button, retain both, report sensitivity and leave correction to the owner. Set votes without exposure history cannot establish three-screen coherence. One owner/one attempt cannot isolate package efficacy or validate a whole design. Track clear rejections and positively observed details without adopting a prototype wholesale.

Deliver the offline viewer, permitted builds/captures, source/diffs, input/protocol/capability manifests, actual QA and reference evidence, hashes, all attempts and a separate private decode. Test export/import/resume/early-stop, wrong-corpus rejection, pending-comment recovery and explicit-next behavior using synthetic-only votes. Test transfer extraction in a new directory, source/build/capture hashes and offline boot. Use explicit UTF-8 and stable line endings; do not let host Git autocrlf change transferred source bytes. Preserve original failed receipts.

For cross-host merging verify identical source, state/save and capture contracts and original capture hashes before deduplicating originals. Stop on differences for explicit resolution. Re-identify artifacts, preserve provenance privately, derive a new corpus and new schedule. An absent host is absent; a synthetic merge test is never a real second-host result.
