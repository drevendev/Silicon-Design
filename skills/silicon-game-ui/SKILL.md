# Silicon game UI

Inspect the current game revision, loop, world, direction, contracts, text and assets. Carry accepted changes, layout/capacity constraints and supplied growth plans; separate speculation. Static screens need no invented flows, surfaces or saves.

## Compose the play decision

Identify genre, input, resolution, viewing conditions, UI scale, safe areas and languages. Prioritise the immediate decision/playfield; keep less urgent detail reachable.

Before expanding multiple screens, reuse or establish a shared kit: semantic colours, type/numbers, icons, density, chrome and components/states. Equivalent navigation, level/XP and controls share implementations; explain task-based differences. Local fixes need no new kit.

Group state, exact quantities and actions; bound rows/cards and remove redundant framing when authorized. A familiar remove glyph or search placeholder may replace repeated visible text while preserving programmatic names, persistent context, targets, input and safeguards. Keep useful empty/blocked explanations. Respect fixed-copy/DOM constraints and report structural limits.

Use expressive material/type with readable operational text. Keep names, costs and effects near decisions. Distinguish resource/weather/action symbols and selection at use size. Compare scenery, objects, icons and controls for edge, lighting, perspective and material coherence; family sheets are optional.

Extend colours coherently or remap the palette within scope. Inspect actual text/glyph colours, SVG fill/stroke/currentColor, masks, filters, crops and inherited backgrounds in affected states. Unreadable dark-on-dark glyphs fail regardless of unrelated passing swatches. Preserve priority after reflow; avoid tiny labels, inflated counts or forcing every action above the fold.

## Preserve game truth

Show effects, owned/required amounts, costs and blocked reasons. Retain exact values or reachable exact disclosure when consequential. Distinguish zero, unknown and not applicable; preserve hidden knowledge/unlock rules in visible and accessible text.

Presentation, hover, focus and help must not change economy, inventory, progression or simulation unless requested. Feedback follows real pending/failed/interrupted/completed events without duplicate purchases or misleading effects. Keep repetition efficient; celebrations must not delay routine input. Invent no events for personality.

## Verify within scope

Exercise affected normal/adverse states, long translations and large/live quantities in the actual runtime when available. Check supported keyboard/controller/pointer/touch, focus/restoration, selection and scaling; address remapping, non-drag paths and motion/audio independence where relevant. Critical information needs cues beyond colour/sound.

Where affected, verify interruption/return, repeated input and promised cross-surface/reload/restart persistence. Preserve useful context and connected visible focus after removal/recovery. Recheck changed shared consumers and report unresolved readability defects.

Deliver contracts, corrections and checked/failed/untested coverage. Static mockups/web simulations do not prove native runtime, controller, saves or comprehension. Assess character separately from correctness/operation; technical checks do not establish attachment.
