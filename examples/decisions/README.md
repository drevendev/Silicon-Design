# Nightjar: inspect the decision, not just the first frame

Original fictional offline teaching examples for [release 2026.11.17.1](../../research/release-2026-11-17.md). No account, service, model, real purchase or third-party art. Source/code/vector material is original under the repository MIT license; system fonts only. These are new teaching artifacts, not historical before/after product evidence or independent model outcomes.

## Brief and composition

Person: a returning workshop visitor choosing a light, then a clerk preparing a reading copy. Intended feeling: a small useful workshop that retains unfinished work without drama. The lantern is the dominant object; exact resource/conditions stay near the decision, full temporal rules live in Inspect. Five fixed offers fit together at the declared 800×600 EN base frame. RU/long/narrow and enlarged text reflow vertically instead of shrinking type. The document desk separates selected workspace, active work and automatic scheduling. Shared colours, system type, native controls, focus treatment and ordinary/error/success grammar live in one CSS file.

Reference boundary: public text reports supply the failure classes; no source game UI or purchased art is represented as visually inspected here. This original fixture is not evidence of autonomous reference discovery. During QA its actual captures were inspected and its duplicate desk history, long-select overflow and enlarged-text overflow were corrected. Consumer reference/generation acceptance remains open in #35/#23.

## Open locally

- [Lantern exchange](exchange.html): choose a physical copy → edit a draft note → exact preview → cancel or accept → separately hang. Stock changes refuse without charge. Guide resumes from lasting state; skip is explicit. Scenario controls demonstrate fixed/in-flow coaching, storage failure and an unreadable original. A diagnostic request is never called a saved backup.
- [Document desk](desk.html): scheduling starts paused. Start runs one simulated attempt; Advance stage supplies its deterministic replies. Select the other workspace during work, request stop, deliver a late reply, then acknowledge release. Outcome notices link to exact attempt/draft; history remains available without duplicating it in the primary view. Change configuration during a pending readiness check to reject stale success.
- [Offline control stress](controls.html): long EN/RU, native select/input/textarea/checkbox/disclosure/dialog, zero/unknown, ₽, dates, emoji, IDs, full source, error and scroll index. Compact preference interaction and category/recipe/disclosure examples preserve meaning. A large white control is explicitly an intentional negative example.

Local storage is scoped to the synthetic sessions. Reset controls clear only the named example session and preserved-original keys. The exchange validates saved structure and exposes an unreadable original without overwriting it on initial load; before a new action saves a fresh session, that exact original is durably preserved separately; failed preservation prevents replacement. The desk's saved state resumes the declared simulated stage; it does not reconnect to a real worker.

## State → feedback / next action

| Case | Visible meaning | Permitted next action |
| --- | --- | --- |
| Draft / exact preview / cancellation | No charge; note and selected copy retained | Edit, inspect, preview again |
| Stale or insufficient stock | Changed conditions; nothing charged | Close, keep draft, refresh preview or choose another copy |
| Accepted but not hung | Required choice remains; no automatic hanging | Hang once; reload preserves the unmet step |
| Workspace A owns work while B selected | Scope named; B's start unavailable | Return to A or request stop; no duplicate job |
| Preparing / processing / checking / saving | Actual simulated stage, no fabricated percentage | Advance deterministic stage or request stop |
| Stopping / stopped | Requested cancellation is not release | Await explicit acknowledgement; late/duplicate replies cannot create a result |
| No input / no match / incompatible | Distinct reason and corrective action | Add source, change selection or inspect supported input |
| Retained draft / process failure / save failure | Different facts, including whether an actual draft exists | Exact attempt/draft reader; no invented saved result |
| Saved simulated copy / idle | Named completed attempt stays discoverable | Open its exact copy and return with focus |
| Old dismissed notice / new attempt | Dismissal belongs to one ID | New result gets its own notice; old result remains in history |
| Configuration changes during check | Prior success cannot certify new configuration | Run and complete a current check |

## Controlled material comparison

The complete single-file artifacts keep identical rules, content, vectors, display size and compression settings:

| Artifact | Treatment | Author decision |
| --- | --- | --- |
| [Plain](exchange-plain.html) | Flat semantic panels; no material halo | Useful fallback and baseline |
| [Engraved](exchange-engraved.html) | Fine inset brass frame around the original vector objects | Selected for this teaching fixture: adds workshop material while focus/selection remain separate |
| [Luminous](exchange-luminous.html) | Warm backing and soft object halo | Retained comparison: glow competes more with the focus treatment; appropriate to explore for a scene, unproven here |

This is author craft judgment after inspection, not a blind vote or evidence of human recognition. The tradeoff is extra framing against plainer operational clarity. Rollback: use Plain; every artifact retains the complete flow. All three contain the same full shared CSS/model family, so their byte costs are nearly identical; this is not an image-pack or asset-optimization benchmark. [Whole-artifact raw, gzip, Brotli and net costs](material-costs.json) include exact hashes. No isolated gzip fragments are summed. Required notice: the repository MIT notice; no purchased pixels, fonts or audio and no external-service exposure.

## Actual verification

See [performed checks and limits](VERIFICATION.md) and [machine receipt](evidence/browser.json). Reproduce with existing Playwright:

```sh
node tools/build_decision_materials.mjs
node --test tests/decisions-model.test.cjs
node tests/decisions.browser.mjs ../decision-evidence
```

`SILICON_BROWSER_PACKAGE` can name an installed Playwright package. The browser harness uses loopback HTTP normally; `SILICON_FIXTURE_FILE_MODE=1` tests file URLs offline when local networking is unavailable. Neither mode makes a model call. Native devices, AT, actual browser zoom, human comprehension/preference and listening remain untested.
