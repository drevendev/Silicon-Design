# Design review checklist

Use this as a prompt for inspection, not a score. Record evidence and applicability in the [review report](../templates/REVIEW.md).

- [ ] The intended person, task and next action are clear in the representative flow.
- [ ] Composition, type, imagery and voice support the product's recorded direction.
- [ ] An intended feeling is connected to specific choices in a real situation.
- [ ] The product has subject-specific material and a recognizable idea beyond a palette or logo.
- [ ] That idea carries through the main task, a difficult state and completion where in scope.
- [ ] Hierarchy distinguishes primary, supporting and optional information.
- [ ] Containers and density follow content relationships and comparison needs.
- [ ] Important text is readable; numbers retain useful units and precision.
- [ ] Supported scripts and long translations work in actual controls and headings.
- [ ] Color roles, relevant contrast pairs and non-color status cues were inspected.
- [ ] Important default, focus, pending, unavailable, empty, error and success states work where applicable.
- [ ] Failed actions explain recovery and preserve useful input.
- [ ] Empty states distinguish first use, completion, no matches, unavailable data and failure where relevant.
- [ ] Voice is coherent and tone respects the situation, especially failure or payment.
- [ ] Repeated use avoids unnecessary tours, waiting, motion and praise; help remains discoverable.
- [ ] Narrow/intermediate/wide layouts or target game resolutions remain useful.
- [ ] Supported input paths work; focus is visible and overlays restore it appropriately.
- [ ] Text enlargement, real zoom and reduced motion were tested or explicitly left untested.
- [ ] Images/icons have coherent roles, provenance where needed and appropriate text alternatives.
- [ ] Product claims use real evidence; examples and prototype actions are labelled.
- [ ] For games, UI scale, scene contrast, knowledge rules and resource feedback were checked in runtime.
- [ ] The report identifies what was checked, what failed and what remains unknown.
- [ ] The report gives separate conclusions on operation and character; static checks are not presented as a taste test.
- [ ] Substantial open-direction work retains same-brief rendered alternatives, with fixed content/capabilities/assets/state/viewport and visible structural tradeoffs.
- [ ] Subject inventory survives comparison with the nearest same-category product.
- [ ] Use-size component/asset/state sheet and a second meaningful surface demonstrate the grammar.
- [ ] A second ordinary task, interruption/return and declared reload boundary were exercised where in scope.
- [ ] Visual findings name a selector/region, expected correction and recapture, marked resolved/partial/unresolved.
- [ ] Comparative quality/diversity claims have matched artifacts and scoped human evidence; otherwise they remain targets.
